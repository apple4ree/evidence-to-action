# 실제 실행의 국소 근거 진단 채점 규격 v1

## 평가 단위와 입력

평가 대상은 `review_ready_ids.json`의 15개 국소 행동/발화다. 실제 원본은 14개이며 MAST-R01과 MAST-R05는 같은 원본으로 묶는다. 데이터별 정답은 `gold/{case_id}.json`, 주석 조정 이력은 `gold_adjudication.json`에 보존한다. 새 비교 예측을 읽기 전에 작성한 LLM 주석 규격이며 사람 정답 검증 결과가 아니다.

모든 방법에 같은 원문 prefix, 대상 행동, 원문 locator, 수집 범위, 중립적인 `focal_relation`을 제공한다. `focal_relation`은 평가할 주장/관계를 지정하며 정답 라벨, 필수 정답 근거, 의미 요소, 채점표는 입력에 주지 않는다. 이는 모든 적용 요구사항의 완전한 정당성을 판정하는 과제가 아니라 지정한 핵심 관계의 진단이다. 중간 전달 위치를 모두 복원하도록 요구하지 않는다.

MAST 입력은 여러 actor의 공개 기록이므로 이를 원래 한 actor의 전체 context로 간주하지 않는다. “공개 기록의 전달 관계에 문제가 있다”와 “수신자가 잘못을 알고 있었다”는 다르다. AgentHallu 질문 그룹의 주입 시점, Who&When 실제 actor payload도 미검증이다. 입력에 관측된 부분 행동의 의미만 채점한다.

## 공통 출력

```json
{
  "decision": "Supported | Unsupported | Indeterminate",
  "issues": [{
    "field": "자연어 또는 도구 필드명",
    "requirement": "평가할 조건/관계",
    "evidence": [{"locator": "/input/history/0/content", "quote": "원문 그대로의 구절"}],
    "relation": "satisfied | violated | unresolved | not_applicable",
    "exception": {"applies": false, "basis": "허용 예외 또는 해당 없음에 대한 설명"},
    "rationale": "해당 근거와 판정의 연결"
  }],
  "rationale": "전체 판정 이유",
  "limitations": ["해당 입력으로 확인할 수 없는 범위"]
}
```

예측 decision은 위 Titlecase 표기를 사용한다. 정답 파일은 lowercase를 사용하며, 채점 시 앞뒤 공백 제거와 소문자 변환으로 정규화한다.

`issues`는 기존 공통 schema 이름을 유지한 **진단 관계 목록**이며 오류 목록만 뜻하지 않는다. Supported에서도 `satisfied` 관계와 근거를 한 개 이상 출력한다. 빈 목록만으로 근거 연결 정답을 인정하지 않는다. `issues`가 존재한다는 이유로 오탐으로 세지 않는다.

MAST 인용은 `/input/prior_record` 또는 원문 `Lstart-Lend` locator와 문자 그대로의 quote를 사용한다. 두 locator 형식을 모두 허용한다. JSON 기반 로그는 `/input/history/{index}/...`, 사용자 task는 `/input/task/...`, 평가할 발화 자체는 `/input/target_action`을 사용한다. 정답 파일에 저장된 원본 locator는 추적용이며, 모델의 인용은 실제 제공한 공개 packet을 기준으로 검증한다.

## 판정

- Supported: 지정한 관계가 관측으로 뒷받침되거나, 대상이 아직 확인되지 않은 정보를 확인하려는 정당한 조회/질문이다.
- Unsupported: 지정한 관계에 명시적 충돌이 있거나, 대상이 직접 인용/의존한 관측의 의미를 변형하여 주장한다. 예: 비밀번호를 토큰으로 재명명, 페이지 범위를 전체로 확장, 요청의 월 경계를 날짜로 변경.
- Indeterminate: 지정한 관계를 확인할 정책/상태가 부족해 실제 충족과 위반을 결정할 수 없다. 예: 계정 소유자 mapping, 공유 디렉터리 위치, 순환 큐의 과거 재생 여부.

과거/미래 정답이나 상식으로 누락 상태를 복원하지 않는다. 기록이 불완전해도 명시적 충돌이 관측되면 Unsupported가 가능하다. 실패 실행에 속했다는 이유만으로 정상 조회를 오류 처리하지 않는다.

P2의 코드 합성: `violated`가 하나 이상이면 unsupported, 그 외 `unresolved`가 하나 이상이면 indeterminate, 유효한 적용 관계가 하나 이상이고 전부 satisfied 또는 not_applicable이면 supported. 빈 관계 목록 또는 전부 not_applicable이면 **합성 실패**로 기록한다. not_applicable은 적용하지 않는 조건이지 검증하지 않은 조건을 숨기는 수단이 아니다. 출력 형식/참조 오류는 technical-invalid로 별도 기록하며 의미적으로 unresolved로 바꾸지 않는다. 재시도는 기술적 실패에만 사전 규칙대로 적용한다.

## 구성요소 채점

각 정답에 2~4개 `semantic_components`가 있다. 다음 항목을 분리하여 기록한다.

1. **판정 정답:** decision이 정답과 같은지, 원시 분모 포함.
2. **의미 요소:** 각 criterion을 의미적으로 충족하는지 pass/fail/unscorable. 같은 설명을 여러 필드에 적어도 의미가 보존되면 허용한다. `recipient`, `message.recipient`, “수신자 선택” 같은 문자열 차이를 오류로 보지 않는다.
3. **근거의 정확성:** 출력 quote가 지정한 입력 위치에 실제 존재하는지 코드로 검사한다. 존재한다는 사실만으로 해당 의미를 뒷받침한다고 채점하지 않는다. 잘못된 인용, 관련 없는 근거, 미래 정보, actor 관측 범위 오인은 별도로 표시한다.
4. **전체 진단 동시 정답:** 판정 정답, 모든 필수 의미 요소 통과, 필수 관계의 유효한 근거 연결, 핵심 설명에 모순이 없음.

정답의 `anchors`와 `evidence_groups`는 검토자를 위한 근거 안내다. **모델이 정답과 동일한 모든 ID 또는 동일한 길이의 quote를 출력해야 한다는 규칙이 아니다.** 같은 관계를 입증하는 다른 유효한 원문 구절을 허용한다. 그룹들은 가능한 근거 경로를 가리키며 의미적 criterion 충족을 먼저 판단한다. 추가적인 모든 요구사항/경로를 나열했다고 가산하지 않는다. 누락된 핵심 의미 요소와 잘못 추가된 관계는 따로 기록한다.

문장 의미 판단은 검수자가 수행하고, 코드는 참조 존재와 집계를 담당한다. 자동 채점기에서 단순 키워드 포함을 의미 정답으로 대체하지 않는다. 의미 검수자는 방법 이름을 가린 예측과 고정된 정답 규격을 보고 판정하며, 예측에 맞추어 정답 기준을 변경하지 않는다. 경계가 해소되지 않으면 unscorable로 남기고 모든 방법에 동일하게 적용한다. 최초 점수와 변경 사유는 보존한다.

## 필수 범위 명시

- **AHN07:** 게시 상태의 결과 보고를 평가한다. 트윗 문구 자체의 정확성이나 앞선 게시 권한 판단은 이 사례의 목표가 아니다. 실제 post_tweet 반환 객체와 “초안, 원하면 게시” 표현의 관계를 본다.
- **WW-new-43-12:** “추출한 자료로 전체 구간을 검증했다”는 귀속 주장을 평가한다. 실제 정류장 수 6의 현실적 진위를 새로 조회하거나 정답으로 삼지 않는다.
- **MAST-R03:** 공개된 페이지 조회, 목록 전달, 전체 부정 결론의 관계를 평가한다. Supervisor가 API 문서를 읽었는지나 실제 미발견 곡 수를 묻지 않는다.
- **MAST-R06:** “현재 곡 뒤에 있음”과 “지금까지 한 번도 재생되지 않음”을 동일시하지 않는다. 원본의 미래 실패 평가를 입력/정답 근거에 넣지 않는다.
- **AHN04, AHN08:** 각각 실제 계정 소유자와 실제 저장 위치가 미확인이다. 보이는 이름 차이 또는 조회 부재만으로 확정 위반을 만들지 않는다.

전체 15건의 공통 입력에 중립적인 focal_relation이 포함되어 있다. 정답의 public_input_sha256은 이 입력을 참조하며, 실행 전 동결 manifest에 데이터, 정답, 프롬프트와 실행 설정의 해시를 함께 보존한다.

## 보고

판정 정확도, 혼동행렬, 오류 재현율(7건), 정상 오탐률(5건), Indeterminate 적중(3건), 불필요한 판단 유보를 원시 분모로 제시한다. 실제 실행 전에 정답 구성이 바뀌면 이 분모도 버전과 함께 고정한다.

의미 요소별 정답 수/전체 수, 근거 참조 오류 수, 전체 진단 정답 수를 별도로 보고한다. unscorable과 technical-invalid를 누락하지 않는다. decision coverage는 유효한 supported 또는 unsupported 수/전체 대상 수이며 판단 유보와 실행 실패를 따로 보고한다.

15개를 독립 실행 15개로 취급하지 않는다. 14개 원본 그룹 단위 결과와 데이터 출처별 결과를 함께 제시한다. 작은 표본의 신뢰구간을 제공한다면 원본 그룹 단위로 재표집하며, 점수 차이를 일반적 우위나 동등성으로 해석하지 않는다. 호출 수, 입력/출력 토큰, 활성 세션 시간 등 실제 측정된 비용만 기록한다. 합성72 결과와 합산하지 않는다.
