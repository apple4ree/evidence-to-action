# 질문 범위 보정, 사후 재채점 v2

공개 질문과 기존 채점 요소를 대조한 뒤 질문 밖의 두 요소만 제외했습니다. 공개 입력, 판정 라벨, 저장 예측과 원점수는 그대로 보존했습니다. **평가 후 발견한 채점 범위 오류에 대한 사후 재채점**입니다.

| 사례 | 공개 질문 | 제거 | 유지 |
|---|---|---|---|
| AHN08 | 파일 위치가 디렉터리 맥락과 연산으로 뒷받침되는가? | normal_value: 숫자 9의 wc 출처 | location_gap, uncertainty |
| AHN09 | 인용된 내용이 파일 읽기 응답으로 뒷받침되는가? | file_link: 검색 파일과 읽은 파일의 경로 | content_preservation |

원래 사용자 업무는 여러 요청을 포함하지만 진단기에 제공된 focal_relation은 위 관계로 한정되어 있습니다. AHN09의 채점용 gold 문구는 관측 파일 자체까지 포함했으나 공개 질문은 읽기 응답과 보고 내용의 관계를 지정합니다. 공개 질문을 넓히지 않고 채점 범위만 맞췄습니다. 남긴 요소의 criterion과 evidence_groups는 원본 그대로입니다.

| 방법 | 판정, 전후 동일 | 전체 진단 원점수 | 전체 진단 보정 |
|---|---:|---:|---:|
| 직접 진단 D1 | 14/15 | 12/15 | 14/15 |
| 재검토 D2 | 15/15 | 13/15 | 15/15 |
| 단계 분해 P2 | 14/15 | 12/15 | 14/15 |

세 방법의 해당 두 응답을 원문과 다시 대조했습니다. AHN08은 폴더 동일성이 가정임을 짚고 위치의 양쪽 가능성을 남겼습니다. AHN09는 읽기 응답과 보고문의 여섯 구절, 순서와 내용 보존을 설명했습니다. 근거, 예외, 모순 여부와 참조 검사도 확인했습니다. 모든 방법에서 남은 요소를 충족하여 전체 진단만 두 건씩 증가했습니다. 다른 지표와 사용량은 변하지 않았습니다.

검토자는 현재 assistant LLM입니다. 저장 응답을 본 사후 검토이며 사람 검수나 방법 이름을 가린 독립 검수는 아닙니다. 사람 라벨 불일치 세 건은 미조정 상태로 별도 유지합니다. 방법의 상대적 순서와 기본 설계 선택은 바뀌지 않았습니다.

## 재현

저장소 루트에서 입력 복원을 먼저 수행합니다.

```sh
python3 real_traces/restore_inputs.py
python3 real_traces/rescore_scope.py
```

원래 평가기는 기본 호출 시 원점수를 재현합니다. 보정 스크립트는 원본 파일 hash와 원점수 재현을 확인한 뒤 보정 gold 두 개와 의미 검토를 덮어읽어 별도 results/에 기록합니다. 새 모델 호출은 없습니다. 변경된 행 6개, 변경 필드, 불변 지표를 assert로 확인합니다.

- `gold/`: 두 사례의 보정 채점 기준. 라벨은 원본과 동일.
- `review_log.json`: 방법별 남은 요소 재검토와 원래/수정 의미 채점.
- `semantic_ratings.json`: 두 불필요 요소만 제외한 전체 의미 채점.
- `original_hashes.json`: 원래 입력, 정답, 예측, 의미 채점과 결과의 hash.
- `evaluate_v1.py`: 수정 전 평가 코드 보존.
- `impact.json`: 원점수, 보정 점수와 바뀐 행.
- `results/`: 사후 보정 집계, 사례별 JSON과 CSV.

원래 자료는 상위 `gold/`, `semantic_ratings.json`, `results/`에서 유지합니다.
